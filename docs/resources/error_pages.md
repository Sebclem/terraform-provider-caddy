# caddy_error_pages

Required `subroute_id`, `root` (directory on the Caddy host) and `page_uri`, typically `"/{http.error.status_code}.html"`. The resource owns one error route and its fixed vars-root, rewrite, file-server and original-status fallback sequence. Root/URI edits preserve the top route ID. Internal IDs derive from the top ID with `-root`, `-rewrite`, `-files`, `-fallback` suffixes; children are not separately managed/imported.

Supports UUID/default `object_id`. Import uses only the top error route's existing ID and requires the complete recognized sequence; partial/custom error handlers are rejected. A subroute must have no other error routes when this resource is created. Deletion removes the owned error route subtree. Files stay external. Caddy serves error files using the original error status; a missing file returns the original error status and empty body, matching the legacy server-level error handler. The internal file server uses pass-through for missing files followed by a fixed original-status responder, because Caddy subroute error handlers otherwise propagate a new 404.
